# Pic Expert

Chrome Manifest V3 扩展：点击扩展图标，自动检测已登录网站的当前商户，显示对应资料导出入口并进入独立任务页。自动识别已登录的银联商务网站标签页，按其当前交易日期和订单状态，先读取**日期和状态范围内的完整订单列表**，再按所选功能下载完整订单资料。

## 规则

- 弹窗显示当前商户名称和商户号。`89813015722APT1` 只显示家电电脑入口，`89813014812B06R` 只显示数码入口。每次打开重新读取商户信息；未登录、无法识别或商户未配置时不显示入口。多个网站标签页时，请在目标网站页打开弹窗。
- 先手动登录、完成查询，再打开对应功能。两个功能分别保留上次任务，不能同时运行；先暂停或停止当前任务，再切换功能。
- 家电电脑沿用下述 SN码、发票和证明材料规则。数码读取模板中所有图片字段，保存所有有值的图片，按资料名称命名；同名字段按模板顺序编号。缺任一模板必填图片时整笔跳过，清单原因列列出缺失项；可选图片为空时跳过该字段。
- 数码资料包括 SN照片、SN与包装盒二合一照片、系统IMEI照片、发票及三类证明材料。手机模板 IMEI 必填，商品模板 IMEI 可选，具体要求以订单模板为准。
- 新任务分别保存到 Chrome 下载目录的 `pic-expert/家电电脑/<日期范围_任务编号>/` 或 `pic-expert/数码/<日期范围_任务编号>/`。任务页面切换功能后显示该功能的进度、结果和日志。
- 弹窗入口按商户号显示。任务页仍可手动选择功能，下载和续传不校验账号或商户号归属。续传仍核对原查询范围和订单列表。运行中登录凭证变化或失效时自动暂停；重新登录并恢复原查询后可继续。
- 升级前的任务归入家电电脑功能，保留原目录和记录。满足查询范围、列表和断点校验的旧任务可继续，不要求账号归属信息。

- 扩展不负责登录、选择或调整日期、点击查询。接口筛选只使用交易日期和订单状态：交易日期必填，订单状态留空表示全部状态。订单号、参考号和提交日期等其他页面筛选项不参与下载范围；扩展不会修改这些控件或切换商户。新任务通过接口整批读取列表并保存到 IndexedDB，列表完整后才读取详情和图片。列表请求失败、总数变化或身份重复时自动暂停。
- 订单列表、详情、模板和图片均通过网站接口读取；扩展不扫描表格来处理订单，也不打开详情页面。
- 每个新任务的下载目录以交易日期区间开头，再接任务编号；图片、清单和日志共用该目录。旧任务续传沿用原目录。
- 四种未通过状态不再直接跳过。状态文字含“材料修改”时正常处理，在下载清单的“原因”列注明；失败或缺图时同时记录具体原因。
- SN 码或发票任一缺失时整笔跳过，不下载半套资料。
- 每个参考号建立独立目录。SN码或发票只有一张时分别命名为 `SN码`、`发票`；识别出多个不同图片地址时全部下载，按模板字段顺序命名为 `SN码-1`、`SN码-2`、`发票-1`、`发票-2` 等，保留实际图片格式的扩展名。相同地址只下载一次。
- “证明材料图一”“证明材料图二”“证明材料图三”有图片时也下载，按原标签命名；空项目跳过，不重新编号。接口字段识别不唯一或读取失败时整笔记为失败。
- 下载图片前按实际内容识别 JPEG、PNG、WebP、GIF、BMP；返回登录页时自动暂停，无法识别的内容或读取失败时该订单记为失败。
- SN码、发票及本单存在的证明材料均先验证再下载；任一下载失败时尝试清理该订单已生成的全部图片，无法清理的文件路径会记录到运行日志。
- 每次任务只生成一份 `下载清单.csv`，仅保留订单号、参考号、处理结果、原因四列；“材料修改”作为备注写入原因列，图片下载完整时仍记成功。文件路径记录到运行日志。
- 默认保存到 Chrome 下载目录下的 `pic-expert/<业务>/<日期范围_任务编号>/`。

## 安装

1. 使用 Chrome 116 或更高版本，打开 `chrome://extensions/`。
2. 开启“开发者模式”。
3. 选择“加载已解压的扩展程序”，选择本仓库目录。
4. 打开目标订单页面，完成登录、日期选择与查询。
5. 在任意网页点击扩展图标，选择“家电电脑资料导出”或“数码资料导出”。
6. 保持订单网站标签页打开，在任务页面点击“开始下载”。

升级至 0.6.0 后需在扩展管理页重新加载扩展。访问权限仍仅包括 `https://service.chinaums.com/*`。

## 页面适配与恢复

- 图标先显示入口弹窗，不自动跳转。选择功能会打开或聚焦对应独立任务页。扩展自动使用图标打开时绑定的网站或原任务的网站标签页；原标签页关闭后，自动使用唯一打开的银联商务标签页。没有可用页面或存在多个无法区分的页面时显示提示。扩展只读取来源页面中唯一的已查询订单列表 frame。
- 列表使用 `queryList`。实测 `size=10000` 可返回全部 5358 笔；这不是接口上限承诺。列表中的 `productJson` 未能直接解析，图片地址仍需详情和模板。详情使用 `queryDtl` 和 `queryTemplateInfo`，图片使用网站的交易材料下载接口。接口请求沿用页面登录令牌；令牌不保存到任务数据或日志。
- 交易日期和订单状态从列表筛选控件读取并映射为网站请求参数。页面未使用其他筛选项时，开始会核对接口返回页与页面当前显示页的订单身份和总数；使用其他筛选项时，以日期和状态的接口结果为准。订单处理只使用完整接口列表。断点保存日期、状态、接口请求大小、总数和已保存列表的订单身份；继续前需恢复相同日期和状态查询。
- 运行期间不要切换页面或修改日期、状态；发生变化时扩展会中断任务。
- 任务页面是独立浏览器标签页，刷新网站不会关闭任务页面。关闭任务页面不影响网站中正在执行的任务，再次从入口弹窗打开任务页可查看持久化进度。来源标签页刷新、跳转或关闭时，后台自动暂停、整理未完成订单，任务页面显示中断原因和恢复步骤；已完成的文件保留，不生成结束清单。检测到登录失效时也自动暂停。重新登录并恢复原日期、状态查询后，在任务页面点击“继续上次任务”。“停止任务”结束当前批次并生成清单。清单下载失败可点击“重试下载清单”。关闭来源网站后，需要重新打开网站、恢复查询，再在任务页面继续。
- 任务页面中展开“运行日志”可查看和复制最近 500 条记录，包含时间、步骤、订单身份、下载路径及错误；关闭任务页面后日志仍保留。完整日志按条持久化，可点击“导出完整日志”，每 5,000 条生成一个编号文本文件；开始新任务后任务页面切换显示新任务。
- 任务完成或停止后，任务页面显示成功、跳过、失败统计和清单下载状态；重新打开任务页面仍可查看当前任务摘要。

## 大批量处理与断点

- 月份和查询条件由用户操作；每批按当前选择的交易日期和订单状态读取接口结果，扩展不会自动跨月查询。
- 新任务先以 `size=10000` 请求所选日期和状态的订单列表，不使用网页的每页条数。若返回总数超过 10000，再以该总数请求完整列表。校验返回条数、总数和重复身份后，持久化完整列表；接口截断结果时暂停，不处理不完整列表。此阶段不读取详情或下载图片。任务页面显示列表读取阶段及已读取数量；列表完整后切换到资料处理阶段，显示订单总数、已处理、正在处理及成功、跳过、失败统计。
- 点击“暂停任务”后停止安排新订单，等待当前最多三笔订单结束；需要中断当前等待时再次点击“立即暂停当前等待”。停止和强制暂停会中断在途请求，清理未完成图片，并记录失败和残留路径。
- 继续前手动恢复原查询，扩展重新通过接口读取完整列表，核对日期、状态、总条数及已保存各页的订单身份。核对通过后处理保存的完整列表，沿用同一任务编号和目录；完成且下载记录确认全部文件仍存在的订单不重复下载，之前各页的失败订单和文件缺失订单会重试。必需图片缺失而跳过的订单保持跳过；旧版因“材料修改”或“缺失或不唯一”而跳过的记录会重新检查。任务已完成但仍有失败订单时，也可点击“继续上次任务”。
- IndexedDB 独立保存完整列表页、订单结果、下载记录和完整日志；任务页面只读取统计及最近 500 条日志。旧版本任务数据自动迁移，迁移失败时保留原数据。
- 固定同时处理最多三笔订单，同一订单最多同时读取两张图片，总计最多六张图片并发读取。每笔订单全部图片验证通过后逐张保存；不同订单可以同时保存。旧任务沿用已保存的列表批次和请求大小，以核对原有断点。图片网络读取临时错误最多额外重试一次，身份和格式错误不重试。
- 下载优先监听完成事件，并周期补查状态以覆盖事件遗漏和后台重启。
- 结束时只生成四列清单，并记录总数、结果统计和历时。失败任务继续后，结束清单会覆盖同一任务目录下的清单文件。
- 断点只针对上次任务；不同月份的新任务不会自动跨批次去重。登录失效、原查询丢失或数据变化时，需要用户处理后重新核对。已保存列表的订单身份或总数变化时会暂停；需要开始新任务以读取变化后的数据。

## 验证

扩展没有运行时依赖。测试使用 Node.js 自带运行器和开发依赖 fake-indexeddb（仅模拟 IndexedDB，不随扩展运行）。首次验证先安装锁定的测试依赖：

```bash
npm ci
```

再执行：

```bash
npm test
```

同时可以执行：

```bash
npm run check
```

网站接口字段或查询控件可能调整；发生变化时需要同步更新接口适配逻辑。

自动化测试覆盖日期和状态筛选、必填日期校验、请求认证和字段映射、完整列表先于详情、列表失败暂停、登录失效自动暂停和重新登录恢复、查询变化停止、断点恢复、防重入、配对回滚和清单恢复，也覆盖三笔订单并发、最多六路图片读取、乱序完成、跨页等待、暂停与停止、文件丢失、旧数据迁移、两万条 IndexedDB 存储及完整日志分段导出。IndexedDB 测试使用模拟实现，并覆盖旧数据库升级及列表事务失败。

0.4.0 已在隔离 Chrome 中通过三笔本地模拟订单的 E2E 验证，使用真实扩展弹窗、IndexedDB 和下载接口。测试验证了登录失效自动暂停、刷新页面并更新登录令牌后继续、已完成订单不重复下载，以及九张图片的参考号目录、名称、编号、内容和清单备注。详见 [测试报告](.scratch/login-expiry/report.md)。真实网站的 88 笔刷新恢复也已验证，详见 [刷新恢复报告](.scratch/login-expiry/refresh-report-88.md)。0.5.0 已在真实 Chrome 中通过 33 笔网站订单的独立任务页、刷新后提示与自动暂停、原任务续传和文件去重验证，详见 [新版刷新测试报告](.scratch/task-page/refresh-report-33.md)。真实网站登录过期、来源标签页关闭和最大并发仍未验证。

最新整批读取版本已在真实 Chrome 验证：一次读取所选日期段全部 165 笔；小批量下载 18 笔全部成功，保存 36 张图片；刷新后自动暂停，用户重新登录并恢复查询后继续，已完成的 10 笔未重复下载。最终目录、图片文件头和 18 条清单核对通过。详见 [整批读取和恢复验证](.scratch/processing-flow/verification-18.md)及[版本记录](CHANGELOG.md)。未执行 1000 笔下载，未单独验证不刷新而仅登录过期。

0.6.0 的 138 项自动化测试及语法检查通过。隔离 Chrome 通过两个真实入口、独立任务、重新登录后人工选择续传、令牌刷新后恢复、缺文件补回和文件内容核对。数码保存 11 张图片，家电电脑保存 6 张图片，并生成四列清单。两个功能的入口回归测试确认：复用控制台时更新为当前来源标签页。详见 [双功能验证记录](.scratch/digital-materials/verification.md)。模拟网站仅调整 localhost 访问权限和来源标签页 URL 匹配；未执行新版真实网站图片下载。

当前接口适配未使用列表快照版本；相同总数且不产生重复身份的数据变动仍可能导致遗漏，扩展无法完全消除这一限制。
